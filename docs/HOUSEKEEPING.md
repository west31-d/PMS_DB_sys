# PMS 청소표

현재 운영 규칙: 정비완료는 공실과 같은 표시로 사용한다. 오늘 청소표는 미정비이면 노랑, 정비완료인 비투숙/당일 퇴실 객실이면 파랑 공실로 표시한다. 계속 투숙하는 객실은 재실, 고장 객실은 고장 표시를 유지한다. 호수 칸 클릭은 공실/미정비를 전환한다. 아래 일정 기반 색상 설명은 과거·미래 조회에 적용하며, 오늘과 인쇄물은 이 운영 규칙을 우선한다.

`객실관리(HK) → 청소표`에서 영업일과 월별 예약현황을 조회한다. 날짜 기본값은 한국 시간의 오늘이며, 고객명은 청소표에 표시하지 않는다. 객실 선택 후 관련 예약 버튼으로 기존 예약 상세를 연다.

## 실제 데이터 모델

- `reservation_room` 한 행이 1실이다. 수량은 행 수로 계산한다.
- 물리 객실은 기존 `reservation_room.room_id`로 연결된다. 중복 배정 테이블이나 `room_count` 컬럼을 추가하지 않는다.
- 배정 기간은 `reservation.check_in` ~ `check_out`이다. 객실 이동 이력이나 실제 입퇴실 시각을 기록하는 모델은 현재 없다.
- `loadHousekeepingData`는 기존 Supabase client와 RLS를 사용한다. 선택 호텔과 선택 월에 걸치는 예약을 조회하고, 예약 객실 조회에는 부모 예약의 호텔·날짜 조건을 함께 적용한다. 1,000행 단위 페이지 조회로 누락을 방지한다.
- Excel 업로드, 예약 데이터 localStorage 저장, 임의 색상 변경은 제공하지 않는다. 앱의 명시적 데모 모드에서는 기존 데모 데이터를 이용한다.

## 일정 기반 계산

예약/재실/퇴실의 유효한 예약 객실을 포함하고 취소와 알 수 없는 상태는 제외한다. 퇴실 완료 예약도 이전 숙박일과 퇴실일을 계산하기 위해 유지한다.

선택일 D에 대해:

- `check_in < D && check_out === D`: 노랑, 퇴실·청소.
- 당일 퇴실이 아니고 `check_in < D && check_out >= D`: 빨강, 재실.
- 나머지: 파랑, 공실.
- `check_in === D`: 색상과 별개로 체크인 표시.
- 고장 객실은 회색이 우선이며, 연결된 예약이 있으면 경고한다.

이는 예약 일정 기준이다. 실제 조기퇴실·객실 이동의 과거 이력을 복원할 수 없다. 현재 정비/고장 상태를 과거 이력처럼 표시하지 않는다. 청소 완료 후에도 일정상 퇴실일 색상은 노랑이며 실제 정비 상태는 객실 상세에서 별도로 확인한다.

월별 예상 재실은 `check_in <= D && check_out > D`이며 호수 미배정도 포함한다. 예상 공실은 판매가능 객실에서 예상 재실을 뺀 값이다. 음수는 초과 예약을 숨기지 않고 그대로 표시한다. 판매가능 객실이 0이면 점유율은 `—`이다.

## 배치와 검증

`특이사항`과 `고장 목록`은 직접 입력하고 `메모 저장`으로 저장한다. `housekeeping_notes`는 호텔·영업일을 키로 사용하며 기존 호텔 접근 권한에 맞춘 RLS와 저장 RPC를 적용한다. 날짜 이동 전에 미저장 내용을 저장해야 한다. 고장 목록의 텍스트 편집은 객실의 판매불가 플래그를 변경하지 않는다.

`인쇄 / PDF`는 원본 HTML의 A4 가로, 6mm 여백, 285mm 지면, 107mm 청소표/64mm 메모/나머지 일별표 양식을 사용한다. 화면 테마와 독립된 인쇄 문서에 원본 색상, 객실번호·체크인 2행, 체크인/체크아웃 합계, 중앙 2개 메모 영역과 원본 순서의 일별표를 렌더링한다. 고장 객실은 회색과 고장 문구로 구분한다. 현재 편집 내용을 출력하며 HTML 문자는 이스케이프한다. 일반적인 객실 배치와 메모는 1장으로 출력하고 매우 긴 메모는 내용 보존을 위해 페이지가 늘어날 수 있다.

객실 선택 후 `정비완료로 변경` / `미정비로 변경`으로 현재 정비 상태를 저장할 수 있다. `pms_update_housekeeping`은 기존 호텔 접근 권한을 검사하고 정비 상태만 변경한다. 과거 기준일을 보고 있어도 변경 대상은 현재 객실의 정비 상태이며 예약 일정 색상은 유지된다.

`roomPosition`은 객실번호에서 층과 1~6번 위치를 구하며 `buildRoomGrid`는 높은 층부터 6칸씩 구성한다. 존재하지 않는 호실은 빈칸으로 남긴다. 비숫자 또는 범위 밖 번호, 중복 위치의 객실도 기타 행에 표시해 숨기지 않는다.

당일 체크인·체크아웃·전일 투숙·예상 재실에 대해 예약실수/배정실수/미배정실수를 비교한다. 잘못된 호텔 또는 객실타입 배정은 유효 배정으로 세지 않는다. 겹치는 배정, 고장 객실 배정, 오늘 체크인 객실의 미정비는 경고한다. 정비 상태는 점유 계산의 근거로 사용하지 않는다.
