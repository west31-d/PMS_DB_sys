# 객실 상태 기준

| 컬럼 | 값 | 의미 |
| --- | --- | --- |
| `reservation.status` | 예약 / 재실 / 퇴실 / 취소 | 예약 전체 진행 상태. 일부 객실만 입실해도 재실 |
| `reservation_room.stay_status` | 예약 / 재실 / 퇴실 / 취소 | 예약에 포함된 각 객실의 숙박 상태 |
| `room.housekeeping_status` | 정비완료 / 미정비 | 청소·정비 상태. 재실 여부와 독립적 |
| `room.is_out_of_order` | true / false | 고장 등 사용 불가 여부 |

공실·재실은 호실에 연결된 예약 객실의 숙박 상태로 판단한다. 예약 전체가 취소·퇴실이면 종료 상태를 우선한다. 예정 퇴실일이 지나도 실제 퇴실 처리 전에는 재실이다.

입실 예정·퇴실 예정·재실 목록과 객실 수는 객실별 상태를 기준으로 조회한다. 여러 객실 예약은 입실 예정과 재실 목록에 동시에 나타날 수 있다. 예약 목록의 상태 배지는 예약 전체 상태를 나타낸다.

객실 현황의 간단한 배지는 고장 → 재실 → 미정비 → 공실 순서로 표시한다. 청소 상태는 별도 열로 확인한다. 대시보드의 객실 현황 막대는 이 우선순위에 따른 중복 없는 분류이며, 미정비 객실 지표는 재실·고장 여부와 관계없이 청소 상태를 집계한다.

입실은 정비완료·정상 객실만 허용하며 청소 상태를 덮어쓰지 않는다. 날짜별 예약 재고는 예약·재실인 객실만 차감한다. 일부 객실의 취소·퇴실은 다른 객실의 재고를 차감하지 않는다.

입실 처리는 한국 시간 기준 체크인 날짜 당일에만 허용한다. 과거·미래 날짜는 화면 버튼과 서버 RPC에서 모두 차단한다. 서버 제한은 `20260918010000_restrict_check_in_date.sql` 적용이 필요하다.

체크인 날짜가 한국 시간 오늘이고 재실인 객실은 상세 화면에서 빨간 **입실 취소** 버튼으로 예약 상태로 되돌릴 수 있다. 다른 재실 객실이 남아 있으면 예약 전체는 재실을 유지하며, 마지막 재실 객실을 되돌리면 예약 전체도 예약으로 바뀐다. 호수 배정·요금·청소 상태는 유지한다. 서버도 당일 조건과 호텔 권한을 검사하며 `20260918000000_cancel_room_check_in.sql` 적용이 필요하다.

## 적용

`20260917030000_separate_room_status.sql`은 기존 마이그레이션 이후에 적용한다. 예약·고객·청구·결제 데이터는 삭제하지 않는다. 기존 공실은 정비완료로, 기존 재실은 청소 이력을 알 수 없어 미정비로 변환한다. 재실 여부는 기존 `stay_status`로 유지한다. 기존 미정비는 유지한다.

이 마이그레이션은 예약 기본값의 앞 공백도 수정하고 입실 및 예약 생성 RPC를 갱신한다. snippets와 초기 객실 데이터는 정리된 구조를 따른다. 과거 마이그레이션은 변경하지 않는다.

기존 재실 객실에 연결된 유효한 재실 기록이 없으면 마이그레이션을 중단한다. 이 경우 해당 객실의 실제 입실 기록을 확인해야 하며, 임의로 공실로 바꾸지 않는다.

프런트엔드와 DB 마이그레이션을 함께 적용해야 한다. 퇴실·취소 및 정비 완료 처리 UI는 별도 기능이며, 이 변경에서 새로 구현하지 않는다. 실제 입실 시각을 기록하는 기능도 없으므로 실 입실 목록의 날짜 필터는 기존 예약의 입실 예정일 기준이다.
