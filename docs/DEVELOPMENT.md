# ThreeSeven Hotel PMS

호텔 프론트용 React + TypeScript + Vite 웹 UI와 기존 Supabase SQL을 함께 관리합니다.

## 실행

```sh
npm install
npm run dev
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. 환경변수가 없으면 **Supabase 객실·타입 동기화본**을 표시합니다.
먼저 로그인·프로젝트 연결된 Supabase CLI로 `npm run sync:rooms`를 실행하세요. 객실·타입은 실제 DB에서 읽고, 예약·결제는 연결 전이므로 표시하지 않습니다. 개발용 샘플은 `VITE_DEMO_MODE=true`로 명시한 경우에만 사용합니다.

```sh
npm run build
npm test
npm run preview
```

## Supabase 연결

1. `.env.example`을 `.env.local`로 복사합니다.
2. `VITE_SUPABASE_URL`과 `VITE_SUPABASE_PUBLISHABLE_KEY`에 프로젝트 URL과 publishable/anon 키를 입력합니다.
3. 개발 서버를 재시작하고 헤더의 계정 버튼에서 기존 Supabase Auth 직원 계정으로 로그인합니다.
4. 이메일이 확인된 직원 계정에 호텔별 접근 권한을 지정합니다. `20260917000000_create_reservation.sql`은 직원별 조회 정책과 예약 저장 함수를 추가하며, 직원 지정 전에는 데이터 접근을 허용하지 않습니다.

**service_role 키나 DB 비밀번호를 VITE\_ 환경변수에 넣지 마세요.** 브라우저에 공개됩니다.
RLS가 모든 행을 숨기면 빈 목록이 표시되며, 오류는 화면에 표시됩니다. 실제 데이터 오류를 샘플 데이터로 대체하지 않습니다.
초기 구현은 직원이 조회할 수 있는 12개 테이블을 1,000행씩 페이지 조회하여 클라이언트에서 결합합니다.
운영 데이터가 커지면 서버 측 검색·페이지 조회와 호텔별 조회 최적화가 필요합니다.
UI의 호텔 선택은 보안 경계가 아니므로 실제 호텔 접근 제한은 반드시 RLS로 적용해야 합니다.

## 구현 범위

- 고정 Sidebar, Accordion 메뉴, 접기, 작은 화면의 메뉴 오버레이
- Top Header 예약 검색, 한국 날짜, 계정 로그인·로그아웃
- 익스프레스 KPI, 입·퇴실 예정 목록, 현재 객실 상태
- 예약/OTA/여행사 목록: 검색, 필터, 정렬, 페이지 이동
- 예약 상세 Drawer: 객실 요금, 예약번호, 부대 이용내역, 결제 조회
- 객실 현황표 상단 예약 버튼과 중앙 팝업: 고객·객실·서비스 입력, 금액 합계, 실제 예약 저장
- 사용 가능 객실·청소표·고장 객실 조회

HashRouter를 사용하므로 URL은 `/#/express/dashboard` 형태입니다. 새로고침 시 서버의 SPA fallback 설정 없이 동작합니다.
전체 메뉴 경로는 `src/navigation.ts`에서 관리합니다. 기존 웹 Route는 없었으므로 새 경로만 추가했습니다.

## 현재 조회 전용 / 미구현

예약 수정·체크아웃·고장 등록·결제 입력은 아직 제공하지 않습니다.
실퇴실 시각, 노쇼 상태, 등록 카드, 일마감, 알림은 준비 중 화면으로 구분합니다.
`rate_type`은 있지만 `reservation_room.rate_type_id`는 현재 SQL에 없습니다. 상세의 요금타입은 연결 준비 중으로 표시하며 금액은 기존 `rate_amount`를 읽습니다.
신규 예약의 `rate_amount`는 객실별 전체 숙박 요금으로 입력합니다. 기존 요금 데이터는 변환하지 않으며 박수 곱셈이나 미수금 계산은 하지 않습니다.
후불도 실제 수납 완료로 간주하지 않습니다.
입퇴실 예정은 선택 날짜 및 현재 예약 상태 기준이며, 재실·정비상태는 현재 값입니다. 과거 시점의 상태를 복원하지 않습니다.
사용 가능 객실은 정비 완료 공실에서 해당 날짜의 배정 예약을 제외한 값이며 미배정 예약은 차감하지 않습니다.
원격 DB 연결/권한 검증과 직원 업무 흐름 확인 후 운영 배포해야 합니다.

## 객실 기준 데이터 동기화

`npm run sync:rooms`는 연결된 Supabase에서 호텔·객실번호·객실타입·현재 정비/고장 상태만 읽어 `public/data/room-catalog.json`에 저장합니다. 고객/예약/결제 데이터와 비밀 키는 저장하지 않습니다. 파일은 Git에서 제외됩니다.
현재 등록된 80개 객실과 STT/STD/DTL 타입을 그대로 표시합니다. DB에서 수정한 뒤에는 명령을 다시 실행하고 화면의 새로고침을 누르세요. 브라우저 새로고침만으로 DB를 동기화하지 않으며, 화면에 동기화 시각을 표시합니다.
`npm run sync:rooms` 실행 후 개발 서버가 켜져 있으면 `node scripts/check-room-catalog.mjs`로 실제 매핑을 검증할 수 있습니다.
실시간 예약 조회를 위해서는 별도로 공개 키, 직원 계정, SELECT/RLS 정책을 연결해야 합니다. 동기화 모드에서는 예약 내역을 표시하지 않으며 샘플로 채우지 않습니다.

## 실 입실 목록

익스프레스의 실 입실 목록은 `reservation.check_in`이 조회 날짜 범위에 포함되고 배정된 예약 객실의 `stay_status`가 재실인 예약을 표시합니다. 예약 전체가 취소·퇴실이면 제외합니다. 최초 범위는 한국 시간 오늘부터 오늘까지입니다.
왼쪽에서 입실 시작/종료일, 고객명, 객실번호, 예약번호, 거래처, 객실타입을 지정한 뒤 조회합니다. 청소 상태와 숙박 상태는 별도로 관리합니다. Supabase live 연결에서는 호텔·입실 날짜를 서버에서 조회한 뒤 객실별 숙박 상태로 필터링합니다.
예약 1건당 1행이며, 여러 객실은 함께 표시합니다. 객실타입/객실번호 조건은 같은 예약객실에 동시에 적용되며 해당 예약의 전체 금액을 표시합니다. 서비스 금액은 예약 단위로 한 번만 합산합니다. 입실시간과 요금타입은 현재 데이터 연결이 없어 —로 표시합니다.
단체·예약자·입실처리자·시장·예약경로·국적·세금 조건은 연결 준비 중입니다. 객실 동기화 모드에는 예약이 포함되지 않으므로 실제 목록은 예약 조회 연결 후 사용할 수 있습니다.
엑셀용 CSV 내려받기, 20건 페이지 이동, 예약 상세 조회를 제공합니다. `PMS_TEST_PORT` 환경변수로 브라우저 검증 포트를 바꿀 수 있습니다.

## 업무 탭

메뉴에서 화면을 열면 상단에 탭이 추가됩니다. 같은 화면은 중복으로 열리지 않으며, 탭을 전환해도 검색 조건과 입력값이 유지됩니다. X로 닫을 수 있고 기본 대시보드 탭은 유지됩니다. 메뉴 선택 후 사이드바는 자동으로 접히며 헤더 메뉴 버튼으로 다시 펼칠 수 있습니다. 브라우저 새로고침 시 탭 상태는 초기화됩니다.

## 예약 등록

오른쪽 상단 **예약** 버튼으로 입력 팝업을 엽니다. 신규/기존 고객, 고객·거래처 검색, 객실타입과 객실 수, 숙박일수, 부대서비스 및 요금 Summary를 제공합니다. 객실타입을 중복 선택하면 수량이 증가합니다. **호수 배정** 버튼으로 별도 창에서 방을 선택하거나 미배정으로 둘 수 있습니다. 숙박일을 변경하면 배정이 초기화됩니다.

객실타입별 **1박 요금**을 직접 입력합니다. 요금타입 연결 없이 단가 × 객실 수 × 숙박일수로 자동 계산하며, 수량만큼 기존 reservation_room 행을 저장합니다. 빈 요금은 저장할 수 없고 무료 객실은 0원을 입력합니다. 기존 원자적 저장 RPC와 고객·예약·객실·서비스 매핑을 유지합니다.

실제 DB 매핑, 요금 조회 계약, 향후 서버 검증 작업, 검증 방법은 [예약 요금 연결 문서](RESERVATION_RATE_INTEGRATION.md)를 참고하세요.

### 개발용 접근과 직원 계정

예약 상세의 각 객실에서 **입실**을 누르면 `reservation_room.stay_status`가 재실로 변경됩니다. 첫 입실 시 예약 전체 상태도 재실이 되며 다른 객실의 입실 상태와 청소 상태는 유지합니다. 미배정·고장·미정비·이미 다른 예약이 재실 중인 객실은 입실할 수 없습니다. `20260917020000_room_check_in.sql`에 이어 `20260917030000_separate_room_status.sql`을 적용해야 현재 화면과 상태 기준이 일치합니다. 상태 정의와 기존 데이터 변환은 [객실 상태 기준](ROOM_STATUS.md)을 참고하세요. `supabase/tests/room_check_in.sql`은 검증 후 전체 롤백합니다.

현재 연결된 프로젝트는 로그인 없는 개발용 조회·예약 RPC 접근을 허용하고 있습니다. 실제 DB와 데모 데이터는 별도 모드입니다.

```sql
-- 개발용 접근 활성화 / 차단 (데이터를 삭제하지 않음)
UPDATE pms_private.development_access SET enabled = true WHERE singleton;
UPDATE pms_private.development_access SET enabled = false WHERE singleton;
```

개발 완료 후 접근을 차단하고 이메일이 확인된 직원에게 호텔별 권한을 지정합니다.

```sql
INSERT INTO pms_private.staff_property_access (email, property_id)
VALUES (lower('직원 이메일'), 1)
ON CONFLICT DO NOTHING;
```

`node scripts/configure-supabase.mjs`는 연결된 프로젝트의 공개키만 `.env.local`에 설정합니다. 기존 파일은 덮어쓰지 않습니다. 비밀키를 브라우저에 제공하지 않습니다.
